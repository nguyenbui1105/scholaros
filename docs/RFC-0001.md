# RFC-0001 — ScholarOS evidence-first foundation

**Status:** Accepted for alpha reference architecture (2026-11-18)  
**Scope:** skill contracts, trusted data boundaries, deterministic reasoning, evaluation and human approval.

## Problem

International students often confront opaque eligibility (visa/citizenship/school), dispersed scholarship portals, essays requiring credible first-person narratives, and deadlines. Generic content generation can fabricate credentials or violate application rules. ScholarOS prioritizes verifiable decisions and student agency.

## Product principles

1. **Evidence before narrative:** every material personal claim links to user confirmation and, when appropriate, a document/source identifier.
2. **Official-source-first:** preserve URL, retrieval time, excerpt, terms and source confidence; never present unsupported eligibility as fact.
3. **Four-state decisions:** eligible, ineligible, unknown and needs verification; only confirmed eligible enters the default ranking.
4. **Scholarship-specific AI rules:** policy may be prohibited, editing-only, assistance-allowed or unknown. Unknown fails closed.
5. **Human-in-the-loop:** no portal submission without explicit contemporaneous student approval and verified provider permission.
6. **Privacy by design:** separate public opportunity facts from highly sensitive personal records; default to minimal retention.
7. **Quality over volume:** optimize application readiness and user effort, not raw submissions or invented acceptance percentages.

## Canonical entities

- **StudentProfile:** student ID, academic attributes, validated fields, consent state.
- **StoryEvent:** date range, situation/action/outcome, narrative themes, direct user quotes, confirmation status.
- **EvidenceRecord:** claim ID, type, immutable source pointer, visibility, verified-by and verified-at.
- **Opportunity:** provider, canonical URL, award details, dates, scope, AI rules, source snapshot.
- **EligibilityRule:** typed rule, source assertion, authoritative excerpt, confidence, last verified.
- **Application:** student, opportunity, stage, tasks, deadline, consent and version history.
- **EssayArtifact:** prompt/rubric, draft provenance, AI-allowed actions, revision history, student approval.
- **AuditEvent:** actor, action, timestamp, structured reason, policy revision and evidence IDs.

## Core state machine

`discovered -> source_verified -> eligibility_checked -> prioritized -> preparing -> student_review -> ready_for_submission -> submitted -> outcome_recorded`.

Any missing evidence or rule change transitions to `needs_verification`. Only an authorized, logged action may advance to `submitted`. Unknown or prohibited AI policy disables draft generation. Submission requires validated portal rules and active user approval, not standing blanket consent.

## Skill runtime contract

Each skill receives a validated JSON envelope: `task_id`, `student_id` (optional for public research), `inputs`, `evidence_refs`, `policy_context`, `requested_at`. It returns `status`, `outputs`, `evidence_refs`, `uncertainties`, `next_actions`, `audit_refs`. The orchestrator enforces timeouts, budgets, least privilege and manual checkpoints. Skills may not mutate application state outside assigned capabilities.

## Workflow and trust boundaries

Untrusted provider web text and uploaded files must be treated as **data**, never instruction. No web page can override system policy or authorize data exfiltration. LLM interpretation is only a proposal; deterministic validation decides eligibility and publication. Separate retrieval, interpretation, verification, and mutation.

## Evaluation

Evaluate at least: eligibility precision with hard-negative F-1 cases; false-positive eligibility rate; source freshness; hallucinated claims per essay; policy violations; deadline error rate; user time saved; completed application quality; actual award outcomes with confidence intervals when sample size allows. Run a manual baseline and an LLM-only baseline, with blinded independent assessment where feasible.

## Non-goals for alpha

No claims of increased win probability, live opportunity catalog, automated bulk submissions, immigration/legal advice, scraping against platform terms, credential collection, or deployed personal-data SaaS.

## Open questions

Which scholarship providers permit automation? What data retention periods are defensible? What rubric evaluator best correlates with trained counselor judgments? What experience is appropriate when AI use is unclear? These questions are blockers for later features, not assumptions.
